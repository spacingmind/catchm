# Plan: M20.1 — UX fixes from M20 visual verification

- Status: active
- Created: 2026-09-25
- Repo: `catchm`, `web/` only.

## Goal

Fix the UX findings recorded in `docs/plans/completed/m20-ui-shell.md`
(Validation) and the PR #3 review, before M21 builds the live view on
top of the same components.

## Scope

1. **Medium:** the `capture_error` banner's "Open settings" lands on
   Recording. Route it to the page that fixes the error: Transcription
   for engine/API-key errors, Recording for audio-source/device errors.
   Keep the mapping simple (e.g. by error kind from the backend
   message or a small client-side classifier). Record the approach.
2. Collapsed sidebar nav buttons: add `aria-label` (today they're
   `title`-only).
3. Pluralization: "1 decisions" / "1 action items" → correct singular/
   plural everywhere counts render.
4. Translation status: takes ~5 s to settle with only a skeleton.
   Show which check is running ("Checking Ollama…") and render each row
   as soon as its own data arrives, instead of blocking on the slowest.
5. The Start popover overlaps the Live view for ~1 s while closing: close
   it before or during navigation so the transition doesn't cover the
   next screen.
6. The sidebar animates `width` (layout). Use a cheaper transition
   (e.g. transform/opacity on the label, or no animation under
   `prefers-reduced-motion`). Keep the collapse behavior identical.
7. Settings → Transcription: the engine hint line ("Runs on this device
   via your Whisper server.") floats between dividers. Attach it to
   the Engine row's description instead of a separate orphan row.

## Acceptance criteria

1. `cd web && bun run build` + lint clean; `go build ./...` clean.
2. Each item verified with a headless-Chromium (Playwright) screenshot
   against an isolated `catchm serve` with seeded data (same method as
   M20's AC3). Replace the affected PNGs in `docs/screenshots/m20/`,
   or add `docs/screenshots/m20.1/`.
