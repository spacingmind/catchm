# Plan: M4.2 — UI polish pass 2

- Status: active
- Created: 2026-09-18

## Goal

A second, small polish pass, same method as M4.1: real issues found by
building the actual UI and driving it in a headless browser with edge-case
data (very long titles, empty required fields), not invented busywork.

## Findings driving this pass

1. **Bug**: the browser tab favicon is still Vite's default purple `/`
   icon (`web/public/favicon.svg`, referenced from `web/index.html`),
   never replaced with the CatchM mascot. Confirmed by reading the built
   `dist/index.html` and `favicon.svg` — it's the stock Vite asset.
2. **Layout bug**: `LiveMeeting.tsx`'s header (`<h1 className="flex
   items-center gap-2 text-2xl font-semibold">`) puts the `Radio` icon
   and the meeting title as flex siblings inside the same `h1` with
   `items-center`. For a short title this looks fine (icon vertically
   centered next to one line of text). For a long title that wraps to
   multiple lines, `items-center` centers the icon against the *whole
   wrapped block's height*, so the icon visually floats next to the
   middle line instead of aligning with the first line — confirmed via
   screenshot with an 80+ character title (icon appeared next to line 2
   of a 3-line wrapped title, clearly misplaced). `MeetingDetail.tsx`
   does not have this problem (its title is a plain heading without an
   inline flex icon), so use it as the layout reference: the icon should
   stay pinned to the top-left of the title text as it wraps, not
   centered against the full wrapped height.

Everything else checked in this round was fine and needs no change:
`NewMeetingDialog`'s submit button already disables correctly on an
empty title (verified), `MeetingList` and `MeetingDetail` both wrap long
titles cleanly with no overflow or misalignment, no console
errors/warnings appeared during any of this pass's interactions.

## Scope

1. Replace `web/public/favicon.svg` with a favicon derived from
   `assets/logo.png` (reuse the same resized asset/approach from M4.1's
   `web/src/assets/logo.png`, or regenerate at favicon-appropriate sizes
   — a single reasonably small PNG or ICO referenced from
   `web/index.html`'s `<link rel="icon">` is enough; you don't need a
   full favicon package with multiple sizes/manifest for this scope).
2. Fix `LiveMeeting.tsx`'s header so the `Radio` icon (plus its M4.1
   pulse dot) stays aligned to the top-left of the title as it wraps,
   instead of vertically centering against the full wrapped block. The
   simplest fix that matches the existing markup: change the relevant
   flex container(s) from `items-center` to `items-start` and give the
   icon a small top margin/padding to visually align its center with the
   first line's cap-height (eyeball it against a screenshot, don't
   guess blindly) — or restructure so the icon sits outside the `h1`
   as a sibling with `items-start` on the parent row, whichever produces
   a cleaner diff against the current component. Verify against both a
   short title (must still look identical to before) and a long
   wrapping title (icon now stays at the top).

Out of scope: everything else — no other visual changes, no new
dependencies, no changes to MeetingList/MeetingDetail/SettingsTranslate/
NewMeetingDialog (all verified fine in this round).

## Acceptance criteria

1. `task web:install && task web:build` succeeds, no TypeScript errors.
2. `task build && task test && task lint` still pass.
3. Manual verification: built `dist/index.html`'s favicon link points at
   a CatchM-branded asset, not the stock Vite SVG; a screenshot of a
   live meeting with a short title looks unchanged from before, and a
   screenshot with a long (80+ char) title shows the Radio icon aligned
   to the top of the title block, not centered against the wrapped
   height.

## Decisions

1. Favicon: reused the existing `web/src/assets/logo.png` (256×256 CatchM
   chipmunk mascot from M4.1) rather than regenerating from scratch.
   Downscaled it to 64×64 with Pillow (`Image.resize(..., LANCZOS)`) and
   saved as `web/public/favicon.png` (~5.8 KB) — plenty of resolution for
   a browser tab icon, no need for a multi-size ICO or manifest per the
   spec's scope. Deleted the stock `web/public/favicon.svg` and updated
   `web/index.html`'s `<link rel="icon">` to `type="image/png"
   href="/favicon.png"`.
2. `LiveMeeting.tsx` header: changed the `h1`'s flex alignment from
   `items-center` to `items-start`, and added `mt-1.5 shrink-0` to the
   icon's wrapping `<span>`. `items-start` pins the icon to the top of
   the flex line regardless of how many lines the title wraps to;
   `mt-1.5` nudges it down to visually center against the first line's
   cap-height instead of sitting flush with the line box top (verified
   by eye against the short-title screenshot, matching the pre-fix
   look). `shrink-0` prevents the icon from being squeezed if the title
   text is very wide. Went with the "small top offset" option from the
   spec rather than restructuring the icon outside the `h1`, since it's
   a 2-line diff against the existing markup.
