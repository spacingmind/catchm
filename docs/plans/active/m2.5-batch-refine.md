# Plan: M2.5 — batch STT refine + final enrich

- Status: active
- Created: 2026-09-18

## Goal

After a meeting ends, produce a more accurate transcript from the full
`audio.wav` (no latency constraint, unlike the live `StreamEngine`), store
it alongside the live transcript without touching the original, and run
a second, "official" enrichment pass over it. This is the second half of
the two-subsystem STT split recorded in `docs/research-stt-translate.md`.

## Scope

- `internal/stt`: `BatchEngine` interface —
  `TranscribeFile(ctx, audioPath string, opts Options) ([]meeting.Utterance, error)`.
  Reuses `stt.Options` (Lang/TranslateTo) already defined for
  `StreamEngine`.
- `internal/stt/engine_whisper.go`: extend `WhisperEngine` (or add a
  sibling in the same file) to implement `BatchEngine` by POSTing the
  whole `audio.wav` file to the whisper.cpp server's file-transcription
  endpoint in one request, mapping returned segments (with start/end
  offsets) to `meeting.Utterance{At: meetingStart.Add(segment.Start), Text: ...}`.
  Test against a fake HTTP server (httptest), not a real binary — same
  pattern as the existing `TestWhisperEngineMapping`.
- `internal/meeting`: add `WriteBatchTranscript(id string, us []Utterance) error`
  and `ReadBatchTranscript(id string) ([]Utterance, error)` writing/reading
  `utterances.v2.jsonl` in the meeting dir. This file is a full overwrite
  each time (batch produces the whole thing in one shot), not
  append-only like `utterances.jsonl`. Never mutate `utterances.jsonl`.
- `internal/batch` (new package): `Refine(ctx, store, id, engine) error` —
  loads the meeting, requires `EndedAt != nil` and `audio.wav` to exist,
  calls `engine.TranscribeFile`, writes the result via
  `store.WriteBatchTranscript`.
- `internal/agent`: add `EnrichMeetingFinal(ctx, store, id) error` —
  same budget-capped-turn shape as `EnrichMeeting`, but the prompt tells
  the agent to call a new MCP tool `read_batch_transcript` (added to
  `NewMcpServer`) instead of `read_live_transcript`, and the resulting
  frontmatter update sets `Meeting.Refined = true` (add this bool field
  to `Meeting`, `yaml:"refined,omitempty"`) so the UI/API can distinguish
  a coarse live-enrich pass from the final one.
- `internal/server`: `POST /api/meetings/{id}/refine` triggers
  `batch.Refine` then `agent.EnrichMeetingFinal` synchronously and
  returns the updated meeting document (404 if meeting not found, 409 if
  still active or no audio.wav).

Out of scope: chunking/overlap for very long audio (assume the
whisper.cpp server's file endpoint handles a full meeting-length file in
one request; if this proves false in practice, chunking with overlap is
a follow-up), translation layer (`internal/translate`/TranslateGemma),
Soniox batch mode (Soniox is realtime-only in this app), automatic
triggering of refine on meeting end (manual/API-triggered only for now).

## Acceptance criteria

1. `task build && task test && task lint` pass; whisper batch client has
   a unit test against a fake HTTP server (no network in CI, no real
   whisper.cpp binary required).
2. `TestBatchEngineTranscribesFile` — fake whisper server returns
   multiple segments with offsets; engine maps them to utterances with
   `At` derived from segment offsets, in order.
3. `TestWriteReadBatchTranscript` — round-trips `utterances.v2.jsonl`;
   confirms `utterances.jsonl` (v1, live) is untouched by a batch write.
4. `TestRefineRequiresEndedMeetingWithAudio` — `batch.Refine` errors on
   an active meeting and on a missing `audio.wav`.
5. `TestEnrichMeetingFinalSetsRefined` — integration test (same style as
   `TestEnrichMeetingIntegration`, requires the `claude` CLI, skips if
   absent) proves the final enrich pass reads the v2 transcript and sets
   `Refined: true` in frontmatter.
6. `TestRefineEndpoint` — HTTP test: 404 unknown id, 409 active meeting,
   200 + updated document for an ended meeting with a fixture audio.wav
   and a fake whisper server wired into the test server.

## Decisions

- Batch output is a full overwrite (`utterances.v2.jsonl`), not
  append-only, because batch transcription produces the whole transcript
  in one pass — there is no cursor to resume from between calls.
- `Refined` bool on `Meeting` (not a separate schema version) is the
  simplest signal that the frontmatter reflects the final enrich pass
  rather than the coarse live one; keeps `SchemaVersion` for structural
  changes only.
- Whisper is the only batch engine in this milestone (Soniox is
  streaming-only per its API design); a `BatchEngine` interface exists
  so a future engine (e.g. a cloud batch API) can be added without
  touching `internal/batch` or `internal/agent`.
