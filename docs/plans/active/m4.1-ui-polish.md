# Plan: M4.1 — UI polish pass

- Status: active
- Created: 2026-09-18

## Goal

M4 shipped a working web UI; this pass fixes concrete issues found by
actually running it in a browser (Playwright, screenshots, seeded
fixture data) rather than adding speculative features. Every item below
traces to something observed, not invented busywork. No new
dependencies, no illustration/animation work beyond a single subtle
CSS pulse — this is a polish pass, not a redesign.

## Findings driving this pass

1. **Bug**: `MeetingList.tsx`'s card subtitle renders `m.engine ||
   "whisper"`. A meeting started with no `engine` at all (e.g. `POST
   /api/meetings {"title":"..."}`, no pipeline ever attempted) still
   displays "· whisper", falsely implying it was transcribed with
   whisper. Verified live: creating such a meeting and viewing the list
   shows "Started ... · whisper" for a meeting that never captured
   anything.
2. **Bug/rough edge**: `formatMeetingSpan` renders full
   `toLocaleString()` (date + time) for both start and end even when
   they're the same calendar day, producing a long redundant string
   ("9/18/2026, 3:25:41 PM – 9/18/2026, 3:25:48 PM") that wraps awkwardly
   mid-"PM" on a 390px mobile viewport (verified via screenshot).
3. **Brand gap**: the app header uses a generic Lucide `Archive` icon
   (`web/src/App.tsx`) instead of CatchM's actual mascot at
   `assets/logo.png` (chestnut-brown squirrel squircle, referenced in
   `docs/brand.md`) — the brand asset exists but isn't used anywhere in
   the web UI.
4. **Brand gap vs. brainstorm doc**: `docs/ui-brainstorm.md`'s "Icons
   and palette" section calls for the mascot to appear "only in
   onboarding, empty states, occasional status moments" — right now it
   appears nowhere, including the empty state ("Your burrow is quiet.")
   which is exactly the place the brainstorm doc calls out.
5. **Missing live affordance**: the live meeting screen's `Radio` icon
   and the list's "Live" `Badge` are static — there's no visual
   confirmation to the user that the app is actually polling/capturing
   right now (verified: nothing in the live view changes appearance
   while polling).
6. **Missing feedback**: `LiveMeeting.tsx`'s "Add note" button gives no
   visible confirmation after a successful submit beyond the textarea
   clearing — easy to miss.

## Scope

1. `web/src/components/MeetingList.tsx`: change
   `{formatMeetingSpan(m)} · {m.engine || "whisper"}` so the engine
   segment is omitted entirely when `m.engine` is falsy (don't invent a
   fallback label; a meeting with no engine has no "· whisper" segment
   at all — just show the time span).
2. `formatMeetingSpan`: when `started_at` and `ended_at` fall on the
   same calendar day (compare via `toDateString()`), render
   `"<date>, <start time> – <end time>"` instead of the full
   date+time on both sides. Different-day meetings keep the current
   full format on both sides.
3. Brand asset: copy `assets/logo.png` into `web/public/` (or
   `web/src/assets/`), resized/compressed to something reasonable for a
   ~20-40px header mark and a slightly larger empty-state use (the
   source is 1254×1254 and ~950KB — use whatever image tool is
   available, e.g. ImageMagick `convert`/`magick`, `sharp` via a small
   bun script, or Python+Pillow, to produce a couple of small PNGs;
   if literally no image-processing tool is available in this
   environment, use the source file as-is via an `<img>` sized down
   with CSS and record that as a decision/tech-debt note rather than
   blocking on it).
4. `web/src/App.tsx`: replace the `Archive` Lucide icon in the header
   with the CatchM logo image (small, static, `<img>` — no animation).
5. `MeetingList.tsx`'s empty state: add the same logo image (a bit
   larger, e.g. 48-64px) above "Your burrow is quiet.", per the
   brainstorm doc's explicit guidance that the mascot belongs in empty
   states. Static image only — no motion.
6. Live affordance: add a small pulsing dot (Tailwind's `animate-pulse`
   utility on a small colored dot — no new animation library, no
   custom keyframes) next to the "Live" `Badge` on meeting-list cards
   and next to the `Radio` icon on `LiveMeeting.tsx`'s header. Keep it
   subtle: one small dot, not a moving mascot or spinner, in line with
   the brainstorm doc's "provide a calm mode" motion-fatigue warning —
   since this is the only motion in the whole app, it doesn't need an
   actual settings toggle, just needs to stay minimal.
7. `LiveMeeting.tsx`: after a successful "Add note" submit, show a
   brief inline confirmation (e.g. a small "Saved" text next to the
   button that appears for ~2 seconds via `setTimeout` then clears) —
   no toast library, just local component state.

Out of scope: any other visual redesign, dark mode, React Router,
mascot animation/illustration beyond the one static image use, a global
toast system, changing any API behavior, changing the Settings/Translate
or MeetingDetail screens (not implicated by the findings above beyond
what's listed).

## Acceptance criteria

1. `task web:install && task web:build` succeeds (or `bun run build` /
   `tsc -b` from `web/`, whichever the existing scripts are), no
   TypeScript errors.
2. `task build && task test && task lint` still pass (this pass doesn't
   touch Go code, but must not have broken anything).
3. Manual verification (screenshots), same method used to find these
   issues: seed a meeting with no `engine` set and confirm the list card
   shows no "· whisper"/engine segment; seed a same-day started/ended
   meeting and confirm the shortened date format renders without
   wrapping badly at a 390px viewport; confirm the logo appears in the
   header and in the empty state; confirm a small pulse renders on a
   live meeting's badge/icon; confirm "Add note" shows a brief
   confirmation.
4. No new npm/bun dependencies were added for the pulse or note
   confirmation (Tailwind utility + local state only per scope item 6/7).

## Decisions

- **Image tool**: no `convert`/`magick`/ImageMagick binary in this
  environment, but Python3 with Pillow (12.2.0) was available, so used a
  one-off Pillow script (`Image.open(...).resize((256, 256),
  Image.LANCZOS).save(..., optimize=True)`) rather than the source-as-is
  CSS fallback. Result: 1254×1254 / ~950KB → 256×256 / ~56KB. One size is
  used for both the header (`size-6`, ~24px) and empty state (`size-16`,
  ~64px) uses — 256px gives headroom for retina displays at either size,
  so a second dedicated asset wasn't needed.
- **Asset location**: `web/src/assets/logo.png`, imported via `import
  logo from "@/assets/logo.png"` so Vite fingerprints/hashes it into
  `dist/assets/logo-*.png` like the existing font assets, rather than
  `web/public/` (no reason for it to be a stable, unhashed URL).
- **Same-day date format**: `"<M/D/YYYY>, <start time> – <end time>"`,
  i.e. `start.toLocaleDateString()` once, followed by
  `start.toLocaleTimeString()` and `end.toLocaleTimeString()` — matches
  the spec's suggested shape and reuses existing `toLocaleString()`-style
  locale formatting rather than a hand-rolled format string.
- **Engine segment omission**: rather than a ternary producing an empty
  string vs. a `·` + engine string inline in JSX, kept it as a small
  template-string expression (`{m.engine ? \` · ${m.engine}\` : ""}`) next
  to the unconditional span text — avoids a nested conditional render
  while still fully omitting the "· engine" segment when absent.
- **Add-note confirmation (scope item 7)**: found that `LiveMeeting.tsx`
  already had a `noteStatus` state + 2s `setTimeout` clear from the
  original M4 scaffolding (commit `cef518a`) — the underlying mechanism
  in finding #6 was already present, just worded "Note added." instead
  of "Saved". Changed the string to "Saved" to match the spec's example
  copy; no new state/logic needed for this item.
- **Live pulse dot**: implemented as a `size-1.5 animate-pulse
  rounded-full bg-current` (badge) / `bg-primary` (LiveMeeting header,
  absolutely positioned over the `Radio` icon) span — Tailwind's built-in
  `animate-pulse` utility, no custom keyframes, no new dependency, per
  scope item 6's constraint.
