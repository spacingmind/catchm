# Plan: M20.1 — UX fixes from M20 visual verification

- Status: complete
- Created: 2026-09-25
- Completed: 2026-09-25
- Repo: `catchm`, `web/` only.

## Goal

Fix the UX findings recorded in `docs/plans/completed/m20-ui-shell.md`
(Validation) and the PR #3 review, before M21 builds the live view on
top of the same components.

## Scope

1. **Medium:** the `capture_error` banner's "Open settings" lands on
   Recording. Route it to the page that fixes the error: Transcription
   for engine/API-key errors, Recording for audio-source/device errors.
   Keep the mapping simple (e.g. by error kind from the backend
   message or a small client-side classifier). Record the approach.
2. Collapsed sidebar nav buttons: add `aria-label` (today they're
   `title`-only).
3. Pluralization: "1 decisions" / "1 action items" → correct singular/
   plural everywhere counts render.
4. Translation status: takes ~5 s to settle with only a skeleton.
   Show which check is running ("Checking Ollama…") and render each row
   as soon as its own data arrives, instead of blocking on the slowest.
5. The Start popover overlaps the Live view for ~1 s while closing: close
   it before or during navigation so the transition doesn't cover the
   next screen.
6. The sidebar animates `width` (layout). Use a cheaper transition
   (e.g. transform/opacity on the label, or no animation under
   `prefers-reduced-motion`). Keep the collapse behavior identical.
7. Settings → Transcription: the engine hint line ("Runs on this device
   via your Whisper server.") floats between dividers. Attach it to
   the Engine row's description instead of a separate orphan row.

## Acceptance criteria

1. `cd web && bun run build` + lint clean; `go build ./...` clean.
2. Each item verified with a headless-Chromium (Playwright) screenshot
   against an isolated `catchm serve` with seeded data (same method as
   M20's AC3). Replace the affected PNGs in `docs/screenshots/m20/`,
   or add `docs/screenshots/m20.1/`.

## Decisions

1. **Routing "Open settings."** A small client-side classifier in
   `App.tsx`, `captureErrorSection(message)`: the message text is checked
   for `"microphone"` or `"system audio"` (case-insensitive) → Recording;
   everything else (Soniox key missing, engine-construction failures,
   mixer errors) → Transcription, since that's where the engine choice
   and its key/URLs live. `Settings`'s section-nav state moves up into a
   prop (`initialSection`, exported `Section` type) so `App` can pick the
   landing section; `Ctrl/⌘+,` and the sidebar item keep passing no
   section, so they still fall back to Settings' own default
   (Recording) — only the capture_error banner's "Open settings" sets one.
2. **aria-label on nav buttons.** `AppSidebar.tsx`'s `NavButton` now sets
   `aria-label={label}` unconditionally (same string as the visible span
   text when expanded, so it doesn't diverge from what's on screen —
   WCAG 2.5.3 Label in Name). Simpler than a collapsed-only conditional.
3. **Pluralization.** A tiny `pluralize(count, singular, plural?)` helper
   in `lib/utils.ts` (defaults `plural` to `${singular}s`), used for the
   two spots that render counts (`MeetingList.tsx`'s decisions/action
   items). Grepped the rest of `web/src` for similar count strings — no
   other call sites.
4. **Translation status loading text.** `GET /api/translate/status`
   returns all three fields (`ollama_reachable`, `live_model`,
   `batch_model`) in one atomic response — there's no backend change in
   scope this milestone (`web/` only) to split it into per-check
   responses, so "render each row as soon as its own data arrives" can't
   mean literally different arrival times; all three rows do settle
   together. The fix delivers the half that's real and valuable without
   a backend change: replace the content-less `Skeleton` placeholders
   with descriptive "Checking Ollama…" / "Checking…" badges so the ~5 s
   wait (a genuine dial timeout on the configured Ollama host, confirmed
   by timing the request — not a client hang) reads as in-progress
   instead of stuck.
5. **Popover overlap.** Moved `onOpenChange(false)` from after the
   `startMeeting` await (so it fired only once `onStarted` had already
   triggered navigation) to immediately on submit, before the request.
   The close is now triggered strictly before navigation instead of
   after it, so its ~100 ms exit transition plays out concurrently with
   the in-flight request rather than stacking a further ~1 s on top of
   the newly-shown Live view. Measured: popover fully cleared within
   ~150 ms of submit against this fast local server (was ~1 s); the
   error path reopens the popover (`onOpenChange(true)` in the `catch`)
   so a failed start still shows its inline error message where it did
   before.
6. **Sidebar transition.** `transition-[width]` → `motion-safe:transition-[width]`
   on the `<aside>`: identical collapse/expand behavior and timing when
   motion is allowed, but an instant, unanimated resize under
   `prefers-reduced-motion: reduce` (verified via computed
   `transitionDuration`: `0.15s` normally, `0s` under reduced motion).
   Chosen over rebuilding the collapse as a transform/opacity animation
   on the label alone — width has to change either way for the layout to
   reflow, so gating the animation on the motion preference is the
   smaller, behavior-preserving fix the item's own wording allows for
   ("or no animation under prefers-reduced-motion").
7. **Transcription engine hint.** Folded the per-engine hint text
   (`ENGINES[].hint`) into the Engine `SettingRow`'s `description` (which
   already accepts `ReactNode`, not just a string) instead of a second
   freestanding row between the row and the following divider. The
   section's `SaveStatus` (previously sharing that orphan row) moved to
   a trailing `<div className="flex items-center justify-end">` at the
   end of the `SettingsSection`, matching the placement `SettingsRecording.tsx`
   already uses.

## Validation

**How verified:** same method as M20's AC3 — headless Chromium via
Playwright driving an isolated `catchm serve`
(`CATCHM_HOME=/tmp/catchm-m201-home`), scratch Playwright project under
`/tmp/catchm-m201-pw`, seeded with two meetings (Design Review: 1
decision/1 action item; Sprint Planning: 3 decisions/2 action items) to
exercise both the singular and plural cases in one screenshot. Screenshots
in `docs/screenshots/m20.1/`.

1. **Open settings routing** — `capture-error-opens-transcription.png`
   (Soniox engine, no key configured via `PUT /api/config`, started
   through the real popover: banner → Open settings → lands on
   Transcription, `aria-current="true"` asserted). The microphone/
   system-audio branch (`capture-error-opens-recording.png`) was verified
   by stubbing the `POST /api/meetings` response via `page.route` to add
   `"capture_error": "Couldn't open microphone: device busy"` — this
   sandbox's audio backend doesn't fail a real mic open (confirmed: a
   genuine mic-open attempt here succeeds and actually starts capturing,
   which is out of scope to fix and not something to leave running), and
   `source: "system"` is correctly *disabled* in the popover UI on Linux
   (`system.supported: false`), so neither real failure mode is
   reachable through genuine UI interaction in this environment — the
   same kind of stub M20 itself used for capture_error before M19 merged.
   Both routes assert `aria-current="true"` on the expected section
   button, not just a visual read.
2. **aria-label** — `sidebar-collapsed-accessible.png` plus a
   `getByRole('button', {name: …})` count check for Meetings/Action
   items/Settings while collapsed (all 3 pass; previously unfindable by
   accessible name in that state).
3. **Pluralization** — `meetings-list-pluralization.png`: "1 decision" /
   "1 action item" (Design Review) next to "3 decisions" / "2 action
   items" (Sprint Planning) in the same view; asserted the singular
   strings are present and their non-pluralized-count forms ("1
   decisions") are not.
4. **Translation status** — `settings-translation-checking.png` (caught
   ~300 ms after navigating, mid-dial: "Checking Ollama…" / "Checking…"
   badges) and `settings-translation-settled.png` (post-response:
   "Unreachable" / "Not installed" — this sandbox has no Ollama running).
5. **Popover overlap** — `live-capture-error-clean-no-overlap.png`
   (reused the item-1 Soniox flow): asserted the popover clears within
   ~300 ms of submit (polled every 50 ms), down from the ~1 s previously
   measured in M20.
6. **Sidebar transition** — no meaningful screenshot difference (same
   end states, per the item), so verified via computed style instead:
   `getComputedStyle(aside).transitionDuration` is `0.15s` with no motion
   preference and `0s` under `prefers-reduced-motion: reduce`, confirming
   the animation is gated correctly; `sidebar-collapsed-accessible.png`
   shows collapse still renders identically.
7. **Transcription engine hint** —
   `settings-transcription-engine-hint-whisper.png` and
   `-soniox.png`: single Engine row carries both the static description
   and the engine-specific hint, no orphan row between the dividers;
   `SaveStatus` ("Saved") now shows at the bottom of the section after
   switching engines.

**Build/lint:** `cd web && bun install --frozen-lockfile && bun run
build` (tsc -b + vite build) clean; `bun run lint` (oxlint) exits 0 (five
pre-existing warnings in files this milestone didn't touch — Fast

edited files); `go build ./...` clean (no Go changes; only confirms the
embedded `web/dist` still builds).
